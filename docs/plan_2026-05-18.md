This plan covers:

  ratified decisions.

- New ADRs (per 2026-05-18 decision to keep ADRs reserved for
  meta-decisions; implementation decisions live in README + AGENTS.md

## Sequencing principle

Dependency-respecting port order, derived from the dependency map in
the inventory:

- `emit-repro-log` ships first because most downstream artifacts cite
  it (ReproLog emission is a precondition of provenance trailers and
  audit-trail aggregation).
- Auditor subagents (six) land before `audit-remediate-loop`, which
  spawns them.
- Methodology skills (eleven) land before `deliver-results`, which
  consumes them.
- Slash commands (now Codex skills, per feature-map item 4) land after
  the skills they invoke.
- Hooks land after the scripts they wrap.
- Configuration + AGENTS.md finalization closes the implementation
  before the final smoke test.

## Phases

### Phase A — Repo foundation + installer

**Files to create:**

- [README.md](../README.md) — project description; install one-liner; "Requirements" section listing required + detected-recommended + detected-optional dependencies; link to AGENTS.md; link to Phase 1 research for the why.
- [AGENTS.md](../AGENTS.md) — repo-level operating instructions for Codex when working in this repo. Target 12–15 KB; well under the 32 KiB cap.
- [CITATION.cff](../CITATION.cff) — de-identified citation file; stub author "Maintainer" until a release identity is decided.
- [LICENSE](../LICENSE) — license file. Default recommendation: MIT (common in research-tooling ecosystems). User to confirm.
- `pyproject.toml` — minimal; declares `tools/` as a package only if needed for the installer.
- `tools/install.py` — stdlib-only Python; copies files into `~/.codex/`, idempotent via content-hash skip, atomic via temp-file-then-rename, supports `--dry-run` and `--scope user|project`.
- `install.sh` and `install.ps1` — thin wrappers that locate Python and exec `tools/install.py`.
- `tools/check_identity.py` — stdlib-only; greps staged or working-tree files for forbidden tokens; exit code 0 = clean, 1 = leak.
- `.pre-commit-config.yaml` — repo-side; wires `tools/check_identity.py` as a pre-commit hook for every contributor.
- `examples/AGENTS.md` — sample AGENTS.md a user can copy or merge into their own `~/.codex/AGENTS.md`. Includes OMX-style mutation markers (per survey recommendation #1) so re-runs of an installer do not trample user prose.

**Reconciliation work folded into Phase A:** update [docs/SCOPE.md](SCOPE.md) to list **six** auditor branches. SCOPE.md currently reads "Five-branch parallel specialist auditors" — the inventory's dependency map and the source-layer `audit-remediate-loop` SKILL.md both wire six (quant + epi + literature-check + reproducibility-verifier + code-reviewer + format-auditor). The literature doc inherits the five-branch phrasing and should be updated for consistency at the same time.

**Entry condition:** Phase 1 research signed off (already true).

**Exit condition / validation gate:** smoke test passes — `git clone` into a temp dir, run `./install.sh --dry-run` (or `.\install.ps1 -DryRun`), confirm planned actions reported; run for real into a sandboxed `CODEX_HOME=$temp/.codex`, confirm files copied; run `tools/check_identity.py` over the working tree, confirm zero matches.

## Cross-cutting work

### De-identification work breakdown

Total components requiring identity-strip pass (from the inventory's PARTIAL classifications): 4 SKILL.md files; an as-yet-uncounted subset of assets across deliver-results, emit-repro-log, and pre-register-hypothesis (the inventory totals are qualitative — see inventory line ~70 for the per-skill asset breakdown; tabulate concrete affected files at port time); 5 slash command bodies; 2 hooks; 8 templates; plus the 12 bootstrap_templates `.tmpl` files reviewed individually for embedded pseudonyms. Each PARTIAL touch happens in the phase that ports its parent artifact; no separate "de-identification phase" — the work is embedded in Phases B–E.

### Identity-hygiene gate (mechanism)

- `tools/check_identity.py` — Python stdlib only. Greps for the forbidden-token set whose canonical definition lives in the script source: the maintainer's pseudonym and surname fragments, the maintainer's GitHub handle, common personal-email TLDs, OS home-directory path patterns (Windows and POSIX), and a curated list of maintainer-specific project-name tokens. Listing the literal tokens in this plan would itself violate the de-identification commitment; the canonical list ships with the script.
- Wired as a `.pre-commit-config.yaml` hook to block commits with leaks.
- Re-runnable as a one-shot CLI for the Phase F final sweep.
- Exit code 0 = clean; 1 = leak; prints `file:line` for each match.

### Validation gates summary

| Phase | Gate | Mechanism |
|---|---|---|
| A | Installer smoke test | Clone → install.sh --dry-run → install.sh into temp $CODEX_HOME → verify file copy + zero identity leaks |

| C | Methodology-skill end-to-end | Invoke `validate-data` against fixture CSV; verify output schema |
| D | Command + Stop-aggregation cycle | Invoke `cite-add` via crossref MCP; trigger Stop hook; restart Codex; verify aggregator emits session_trail |
| E | AGENTS.md byte cap + config.toml round-trip + project-scaffold | Byte count under 32 KiB; `.codex/config.toml` parses as valid TOML; per-subdirectory AGENTS.md discovered correctly via scaffold integration test |
| F | Fresh-clone smoke test + final identity grep + CITATION.cff verify | Clean clone → install → audit-loop on fixture; identity grep returns 0 matches; CITATION.cff verified de-identified |
